# Content manifests

```bash
node scripts/generate-manifests.js
```

Regenerates the generated manifests from the content files — `content/dictionary/manifests/`
and `content/paint-playground/backgrounds.json`. **Run it and commit the result** after adding,
removing or renaming a dictionary entry, or after changing the paint-backgrounds folder.

`content/puzzle/manifest.json` is hand-maintained — name, grids and image need human input — so
the generator only reports entries whose image file is missing.

⚠️ The old `content/lessons/` format and its `index.json` were retired; every activity now uses
`content/learnings/`.

## Learnings have no manifest

Adding, removing or renaming a learning needs **no** regeneration step. `content/learnings/` is
read directly: `check-learnings-reachable` walks the directory, `validate-json` schema-checks
each file in it, and the Curriculum Coverage page (`app/curriculum/`) builds from the learning
catalogue (`content/learning-catalogue/`).

## ⛔ The gotcha: `check-manifests` does not check everything

The CI gate only diffs `content/dictionary/manifests/`. The paint-backgrounds manifest is
regenerated by the same script but diffed only by `.githooks/pre-push`, so it can drift on a
push that skips the hook.
